# 测试用例

这些提示用于验证触发、范围判断、题材适配和修复分支。每次测试都应在独立会话或干净输出目录执行，避免污染已有资料库。

## 用例 1：全书通用设定蒸馏

> `D:\资料\某部长篇小说.txt`，帮我做全书设定蒸馏：我要所有人物、关键事件、地点、势力、物品、能力/规则、术语和大事年表，最后还想导入世界书。

预期：触发本 skill；先检查编码、章节、规模和题材；根据原文实际内容确定分类；创建新输出目录；默认先说明全书规模和试点/全量选择；若用户明确全量，则分块、并行提取、两级合并、终审输入覆盖校验，再生成 Markdown，JSON 放在 Markdown 卡片和索引通过审计后生成。

## 用例 2：限定类别与题材适配

> `E:\小说\某科幻长篇.epub` 已经转成 `E:\小说\某科幻长篇.txt`，我只想要人物关系、关键地点、科技/能力规则和时间线，不要逐章剧情复述。

预期：触发本 skill；范围缩小为用户指定的类别；使用适合原文的“科技/能力/规则”字段，不强行创建不相关分类；仍保留章节或场景来源；不生成无关的大量卡片；在 Markdown 卡片和索引通过审计后再生成可选的 World Book。

## 用例 3：事件和人物冲突

> `F:\资料\推理小说.txt` 中有多个案件、同名人物和前后矛盾的证词。请提取人物、案件、地点、线索和时间线，保留证据，不要替我判断原文没有说明的真相。

预期：触发本 skill；“案件”归入事件/情节类别；分别记录人物身份、地点、线索和证词来源；冲突对象标记待复核；不把推断写成事实；最终报告区分确定遗漏、疑似遗漏和原文矛盾。

## 用例 4：修复旧蒸馏库

> 我之前蒸馏的资料库可能漏了第四卷，索引链接也坏了。请审查 `D:\旧项目\小说-蒸馏\`，补齐来源、合并别名、修复索引，但不要覆盖原始 TXT。

预期：触发修复分支；先建立基线和备份；检查分块连续性、合并标题层级、终审输入是否覆盖全部实际合并来源；分片重建受影响卡片；处理同名和别名冲突；重建索引；用审计脚本报告确定遗漏、疑似遗漏和原文矛盾。

## 用例 5：自定义分类与严格审计

> `D:\资料\推理小说-蒸馏\` 使用 `audit-config.json`，把“线索”作为卡片分类，把“证人证词”作为事件字段。请检查来源 manifest、流水线状态、所有索引链接和未被索引的卡片；审计失败时返回非零状态。

预期：读取配置中的自定义分类、字段、章节正则和输出路径；不创建默认题材专用分类；`--strict` 在缺失证据、manifest、状态字段、索引覆盖或分块编号时返回 1；根目录不存在时返回 2。
