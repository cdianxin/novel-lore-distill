# 测试用例

这些提示用于验证触发、范围判断和修复分支。每次测试都应在独立会话或干净输出目录执行，避免污染已有资料库。

## 用例 1：全书设定蒸馏

> `D:\资料\某部长篇小说.txt`，帮我做全书设定蒸馏：我要所有角色身份卡、所有副本、所有怪物/能力、势力、道具、术语和大事年表，最后还想导入酒馆。

预期：触发本 skill；先检查编码/章节/规模；创建新输出目录；默认先说明全书规模和试点/全量选择；若用户明确全量，则分块、并行提取、两级合并、终审输入覆盖校验，再生成 Markdown，JSON 放在 Markdown 审计完成后。

## 用例 2：只做副本与世界书

> `E:\小说\鬼故事.epub` 已经转成 `E:\小说\鬼故事.txt`，我只想要副本卡、鬼的规则和 SillyTavern 世界书，不要人物长传记。

预期：触发本 skill；范围缩小为副本/鬼/规则；仍保留来源章节；不生成无关的大量角色卡；World Book 在 Markdown 卡片和索引通过审计后再生成。

## 用例 3：修复旧蒸馏库

> 我之前蒸馏的资料库可能漏了第四卷，索引链接也坏了。请审查 `D:\旧项目\小说-蒸馏\`，补齐来源、合并别名、修复索引，但不要覆盖原始 TXT。

预期：触发修复分支；先建立基线和备份；检查分块连续性、merge 标题层级、终审输入是否包含所有 merge 来源；分片重建受影响卡片；处理同名冲突；重建索引；用审计脚本报告确定遗漏、疑似遗漏和原文矛盾。
