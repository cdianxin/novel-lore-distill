# 卡片与中间文件规范

## 分块提取文件

```markdown
# chunk-NNN 提取（第X章—第Y章）
## 一、人物/角色出现
### 姓名或原文称呼
- 身份/别名：
- 目标/动机：
- 关系与所属：
- 能力/技能/资源：
- 本块关键经历：
- 章节或场景范围：
## 二、事件/情节/任务
### 事件名
- 事件类型：
- 起因/目标/触发条件：
- 地点或场景：
- 参与者与关联势力：
- 关键经过：
- 规则、限制或关键线索：
- 结果/影响/后续：
- 章节或场景范围：
## 三、地点/场景
### 地点名
- 类型与位置：
- 功能/环境/重要场景：
- 历史变化：
- 关联人物、事件与势力：
- 章节或场景范围：
## 四、势力/组织/阵营
### 势力名
- 类型、目标与立场：
- 成员与结构：
- 资源与行动方式：
- 对外关系：
- 章节或场景范围：
## 五、物品/资源/技术
### 名称
- 类型、外观或定义：
- 来源/持有者/流转：
- 功能与影响：
- 使用条件、限制或代价：
- 章节或场景范围：
## 六、能力/技能/制度/规则
### 名称
- 适用对象与来源：
- 作用与表现：
- 触发条件、限制、代价或例外：
- 发展、变化与失效条件：
- 章节或场景范围：
## 七、术语与世界观
### 术语
- 定义：
- 首次或主要出现位置：
- 关联实体：
- 仍待确认的含义：
## 八、大事记/时间线
- 时间或章节：
- 事件：
- 参与者：
- 影响与来源：
```

## 事实等级

- **核心**：多章节、多来源或主线关键实体。
- **次要**：有明确身份和至少一项行动、关系或作用，但不是主线核心。
- **仅提及**：只出现名称、称呼或一次转述，资料不足以建立完整卡。
- **待复核**：来源之间存在身份、时间、关系、能力或结局冲突。

## 来源字段

来源至少保留：

```markdown
## 来源
- merge-NN.md：第X-Y章合并记录；对应分块 chunk-NNN-NNN。
- 原始章节或场景：第X章、第Y章。
```

不要写无法回溯的“根据原文”。如果引用的是场景、卷次或文件范围，也要写出可定位的范围。

## 冲突记录

```markdown
## 冲突与边界
- 早期记录：……（章节或场景）
- 后期记录：……（章节或场景）
- 判定：资料未说明是否为同一实体，保留两种说法并标记待复核。
```

## 文件命名

Windows 文件名禁止 `\ / : * ? " < > |`。替换为全角符号、短横线或下划线，并在卡片中保留原始名称。文件名安全化不能改变实体主名。
