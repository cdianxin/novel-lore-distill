# 卡片与中间文件规范

## 分块提取文件

```markdown
# chunk-NNN 提取（第X章—第Y章）
## 一、人物/角色出现
### 姓名或原文称呼
- 身份/别名：
- 目标/动机：
- 关系与所属：
- 能力/技能/资源：
- 本块关键经历：
- 章节或场景范围：
## 二、事件/情节/任务
### 事件名
- 事件类型：
- 起因/目标/触发条件：
- 地点或场景：
- 参与者与关联势力：
- 关键经过：
- 规则、限制或关键线索：
- 结果/影响/后续：
- 章节或场景范围：
## 三、地点/场景
### 地点名
- 类型与位置：
- 功能/环境/重要场景：
- 历史变化：
- 关联人物、事件与势力：
- 章节或场景范围：
## 四、势力/组织/阵营
### 势力名
- 类型、目标与立场：
- 成员与结构：
- 资源与行动方式：
- 对外关系：
- 章节或场景范围：
## 五、物品/资源/技术
### 名称
- 类型、外观或定义：
- 来源/持有者/流转：
- 功能与影响：
- 使用条件、限制或代价：
- 章节或场景范围：
## 六、能力/技能/制度/规则
### 名称
```

## 事实等级

- **核心**：多章节、多来源或主线关键实体。
- **次要**：有明确身份和至少一项行动、关系或作用，但不是主线核心。
- **仅提及**：只出现名称、称呼或一次转述，资料不足以建立完整卡。
- **待复核**：来源之间存在身份、时间、关系、能力或结局冲突。

## 所有正式卡片的证据字段

每张正式卡片都应在实体状态之后保留稳定的 `实体 ID`，并用逐条证据替代无法回溯的总括性来源。`实体 ID` 在资料库内保持不变；实体合并或拆分时，在冲突记录中说明旧 ID 与新 ID 的关系。

```markdown
## 实体 ID
character-001

## 证据
- evidence_id: E-001
  source_file: 原始文件.txt
  source_chunk: chunk-001.txt
  source_chapter: 第十二章
  locator: 场景标题、段落或页码
  evidence_type: direct / paraphrase / inference
  confidence: high / medium / low
  fact_status: fact / reported / inferred / disputed
  note: 这条证据支持的具体事实
```

`source_file`、`source_chunk` 和 `source_chapter` 应尽量同时保留；至少要有一个来源文件和一个可定位的分块、章节、场景或页码。`evidence_type` 区分直接引文、转述和推断，`fact_status` 区分原文事实、角色转述、分析推断和争议说法。证据不足时降低置信度或标记“待复核”，不要把推断写成事实。

## 来源字段

来源段落用于给人阅读，证据段落用于机器审计；两者都要保留：

```markdown
## 来源
- merge-NN.md：第X-Y章合并记录；对应分块 chunk-NNN-NNN。
- 原始章节或场景：第X章、第Y章。
```

不要写无法回溯的“根据原文”。如果引用的是场景、卷次或文件范围，也要写出可定位的范围。正式卡片至少包含 `实体状态`、`实体 ID`、`证据` 和 `来源` 四个通用区块；分类字段仍按下方模板取舍。

## 冲突记录

```markdown
## 冲突与边界
- 早期记录：……（章节或场景）
- 后期记录：……（章节或场景）
- 判定：资料未说明是否为同一实体，保留两种说法并标记待复核。
```

## 文件命名

Windows 文件名禁止 `\ / : * ? " < > |`。替换为全角符号、短横线或下划线，并在卡片中保留原始名称。文件名安全化不能改变实体主名。
